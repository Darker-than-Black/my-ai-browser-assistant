# MAD — My assistant Dima 😺

Контекстний AI-помічник у бічній панелі Chrome на базі Gemini API. Аналог браузерного розширення Claude: допомагає знаходити інформацію на сторінці, аналізувати контент та (у планах) виконувати прості дії — тестувати фічі, генерувати звіти.

> Статус: **MVP**. Базовий чат із текстом, зображеннями та читанням контексту сторінки працює.

## Можливості (поточні)

- 💬 Чат із Gemini у нативній бічній панелі Chrome (Manifest V3 Side Panel).
- 🖼️ Вхід: текст + зображення (кнопка або вставка `Ctrl/Cmd+V`).
- 📝 Вихід: відформатований Markdown (заголовки, списки, код, посилання, жирний/курсив).
- 📄 Контекст сторінки: одним кліком підтягує `innerText` активної вкладки у запит.
- ⚙️ Налаштування: API-ключ + вибір моделі, зберігаються локально (`chrome.storage.local`).
- 🗑️ Очищення історії, збереження контексту діалогу в межах сесії.

## Авторизація

MVP використовує **Gemini API ключ** (з [Google AI Studio](https://aistudio.google.com/apikey)). Ключ зберігається лише локально у браузері користувача, нікуди не передається окрім запитів до `generativelanguage.googleapis.com`.

Google OAuth свідомо **не** в MVP: side-panel-only розширення не може безпечно тримати OAuth-секрети; потрібен окремий бекенд-проксі (див. [`TASKS.md`](./TASKS.md)).

## Архітектура

```
gemini-sidepanel/
├── manifest.json      # MV3: дозволи (sidePanel, storage, activeTab, scripting), host для Gemini API
├── background.js      # Service worker: відкриває панель по кліку на іконку
├── sidepanel.html     # Розмітка UI (чат + екран налаштувань)
├── sidepanel.css      # Темна тема
├── sidepanel.js       # Логіка: стан, виклики API, рендер, вкладення, контекст сторінки
└── markdown.js        # Власний XSS-безпечний Markdown → HTML рендерер (без зовнішніх залежностей)
```

### Потік даних

1. Користувач вводить текст / додає зображення / тисне 📄 (контекст сторінки).
2. `sidepanel.js` будує масив `contents` (історія діалогу + `inlineData` для зображень).
3. `fetch` POST на `…/models/{model}:generateContent` з ключем у хедері `x-goog-api-key`.
4. Відповідь рендериться через `renderMarkdown()` (спершу екранує HTML, тоді застосовує Markdown — тому вивід моделі не може інжектити розмітку).

### Чому власний Markdown-рендерер

CSP Manifest V3 забороняє inline-скрипти й ускладнює підключення CDN. Замість зовнішнього `marked.js` — компактний локальний рендерер у `markdown.js`, який спершу HTML-екранує текст (захист від XSS), тоді застосовує обмежений набір правил. Посилання дозволені лише `http(s)`/`mailto`.

## Встановлення (dev)

1. `chrome://extensions`
2. Увімкнути **Developer mode** (вгорі справа).
3. **Load unpacked** → вибрати теку проєкту.
4. Клік на іконку розширення → панель справа → ⚙️ → вставити API-ключ → **Зберегти**.

Після зміни коду — **Reload** розширення на `chrome://extensions`.

## Дозволи та приватність

| Дозвіл | Навіщо |
|---|---|
| `sidePanel` | нативна бічна панель |
| `storage` | зберегти API-ключ і вибір моделі локально |
| `activeTab` + `scripting` | прочитати текст активної вкладки для контексту (лише коли натиснуто 📄) |
| `host_permissions: generativelanguage.googleapis.com` | виклики Gemini API |

Жодні дані не надсилаються третім сторонам, окрім запитів до Gemini, які ініціює сам користувач.

## Моделі

Дефолт — `gemini-3.8-flash`. Змінюється в ⚙️. Якщо API повертає *"model is no longer available"*, оберіть актуальну модель у налаштуваннях і збережіть.

## Відомі обмеження (MVP)

- Немає стрімінгу — відповідь приходить цілком.
- Тільки **читання** сторінки; дій (клік, заповнення форм) ще немає.
- Вивід — текст/Markdown; генерація зображень не підтримується.
- Історія не персистентна між перезапусками панелі.
